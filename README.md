# WinterVoice

WinterVoice is a native macOS dictation app with a primary window, menu-bar utility, and non-activating recording overlay. Hold the global **Right Option** key, speak, then release it; Apple Speech recognizes the audio on-device and WinterVoice inserts the result into the text field that was focused when dictation began.

> **Status:** working MVP implementation. The project builds and its framework-light state-machine tests pass with Xcode 26.5. Global hotkeys, privacy prompts, microphone capture, on-device recognition, and cross-app insertion require manual verification in a signed local run because macOS mediates those capabilities interactively.

The original future-platform architecture, domain, roadmap, and security specification is preserved in [docs/architecture-spec.md](docs/architecture-spec.md). This README describes the implemented MVP.

## MVP behavior

- Native primary window with a `NavigationSplitView` sidebar for Overview, Permissions, Transcription, Hotkey, and Privacy. The window opens at launch and can be reopened from the menu bar or with Command-0.
- Models, Remote Providers, History, and Dictionary are discoverable roadmap pages explicitly labeled Planned; none exposes non-working controls or mock data.
- Menu-bar utility with live dictation status and actions to open WinterVoice, open Settings, or quit. The app has no Dock icon (`LSUIElement`).
- Right Option push-to-talk via a listen-only Quartz event tap. The physical key is identified by key code 61, transitions are edge-deduplicated, and disabled event taps are re-enabled or surfaced as unavailable.
- A non-activating floating `NSPanel` displays preparing, recording, processing, inserting, and failure states.
- Apple Speech recognition with `requiresOnDeviceRecognition = true`, only after `supportsOnDeviceRecognition` succeeds. WinterVoice never falls back to remote recognition.
- Text insertion into the originally focused Accessibility element. Direct selected-text insertion is attempted first. Clipboard/Command-V fallback runs only after reactivating the original app and verifying that the exact captured AX element is still focused.
- Clipboard fallback snapshots all pasteboard item types that expose data, restores them after paste, and avoids overwriting a clipboard changed by another app or the user in the meantime.
- Settings for Microphone, Speech Recognition, Input Monitoring, and Accessibility status, requests, explanations, and direct System Settings routes. Input Monitoring observes the hotkey; Accessibility is separately required for safe cross-app insertion.

## Architecture

The app uses SwiftUI-appropriate VIPER and constructor composition:

```text
AppContainer
├── AppShell: View, Presenter, Interactor (navigation and capability presentation)
├── View: MenuBarView, RecordingPanelView, Settings/Permissions views
├── Presenter: DictationPresenter (shared live dictation and permission state)
├── Interactor: DictationInteractor (dictation use-case and state coordination)
├── Router: AppRouter (app navigation and System Settings routes)
├── Entities: DictationState, permissions, insertion target
└── Platform adapters
    ├── RightOptionEventTap
    ├── AppleSpeechTranscriber
    ├── SystemTextInjector
    └── SystemPermissionManager
```

Views render Presenter state and emit actions. The Presenter does not own capture or use-case sequencing. The Interactor coordinates the use case behind a small interface and does not touch Apple frameworks directly. Platform details remain in adapters, and `AppContainer` is the only constructor composition root. There are no MVVM-named types or third-party runtime dependencies.

## Requirements

- Apple Silicon Mac first
- macOS 14 or later
- Xcode 26.5 tested (a recent Xcode with Swift 6 support is expected)
- A locale for which Apple Speech reports on-device recognition support

## Build and test

Open `WinterVoice.xcodeproj` in Xcode, select the WinterVoice scheme, configure your development team/signing, and run the app. For a non-signing command-line compile and test:

```sh
xcodebuild \
  -project WinterVoice.xcodeproj \
  -scheme WinterVoice \
  -configuration Debug \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath /tmp/WinterVoiceDerived \
  CODE_SIGNING_ALLOWED=NO \
  build test
```

The committed Xcode project is generated by `scripts/generate-project.rb` using the host's Ruby `xcodeproj` gem. This is a development-time project-generation convenience, not an app dependency. The generated project uses deterministic UUIDs and is committed, so normal users do not need the gem.

## First run and manual verification

1. Build and run from Xcode with local signing. Confirm the WinterVoice window appears with a native sidebar, then close it and reopen the same window from the menu bar and with Command-0.
2. Visit every sidebar destination. Confirm Overview shows live status/readiness; Permissions has working permission actions; Transcription reports Apple Speech, On-device, current locale/support, and no network fallback; Hotkey shows a fixed Right Option binding; Privacy describes actual local and safe-insertion behavior. Confirm Models, Remote Providers, History, and Dictionary say Planned and offer no operational controls or mock data.
3. Request Microphone and Speech Recognition access. Request Input Monitoring, enable the exact signed WinterVoice build in System Settings → Privacy & Security → Input Monitoring, and separately enable it under Accessibility. Return to WinterVoice after each change; app activation rechecks trust and recreates a stale pre-permission event tap. If macOS explicitly says the app must quit, relaunch the same signed build.
4. Before Input Monitoring is enabled, confirm Overview, Hotkey, Permissions, and the menu bar do not claim the hotkey is listening even if the process can create a listen-only event tap. After enabling it and returning to the app, confirm the status changes to “Listening for Right Option” without an ordinary app restart.
5. In TextEdit, focus an empty document. Hold the physical **Right Option** key, confirm the panel shows Preparing then Recording, speak, and release. Confirm Processing and Inserting appear and text lands in the original document.
6. Repeat dictation at least five times to exercise audio/event-tap cleanup. Also press Left Option and verify it never starts dictation. Leave both Option keys released when returning from System Settings so no modifier edge is ambiguous.
7. Put rich content and text on the clipboard, dictate into an app that requires paste fallback, then verify the prior clipboard content is restored. During another fallback, copy something new while processing and verify WinterVoice does not overwrite that newer clipboard.
8. Start dictation in one field, then move focus before insertion. If AX direct insertion cannot succeed, fallback must show a failure and paste nowhere because the original field is no longer focused.
9. Use a locale without on-device support, if available. Confirm a visible unsupported/offline failure and no remote transcription attempt.

## Scope and roadmap

The MVP intentionally includes only Apple on-device Speech. Remote providers, downloadable models, whisper.cpp, history, custom dictionaries, LLM processing, Screen Recording, login items, configurable hotkeys, and live waveform visualization remain roadmap work. Their sidebar pages provide honest discoverability only. No speculative provider/model infrastructure ships in this MVP.

## Privacy and limitations

Audio is fed directly from `AVAudioEngine` to Apple Speech with on-device recognition required; WinterVoice contains no network transcription path. Transcription text is not persisted or logged.

Accessibility behavior varies by target app. Direct insertion uses the captured focused AX element. Paste fallback is deliberately bounded: it reactivates the original application and proceeds only if that exact AX element is still focused. This protects against text being pasted into the wrong field, but means apps that replace their Accessibility element during focus restoration will fail safely and require another dictation.

Clipboard restoration preserves pasteboard representations available as raw data. macOS pasteboard promises or provider-backed values that cannot be materialized as data are not representable by this MVP; fallback still avoids clobbering any clipboard changed after WinterVoice writes its temporary text.
